# HivePlane v0.2.0 — Field Test Directory

This directory holds the field-test plan, the container-layer (Docker) test plan, and
the execution artifacts/reports for **M61** (the Complete Fleet OS field test). It is
organized for **repeatability**: anyone can rerun the field test by following this
directory and the two plans.

Companion to [PRD 09 Roadmap](../../prd/09-roadmap.md) (34 release gates) and
[WBS Part 19](../../wbs/v0.2.0/wbs-v0.2.0-part19-field-test-release.md) (M61–M62).

## Goal

Prove the **Complete Fleet OS** against a live stack: the fleet **runs itself** (triggers,
pipelines, GitOps reconciliation), **defends itself** (drift, injection, policy, kill
switches), **explains itself** (cost/ROI, reporting), and **scales itself** (tenancy,
distributed workers, Helm) — then sustain **≥50 concurrent runs** with no correctness
failures.

The field test covers 25 scenarios (S1–S25) plus a concurrency load test, mapping every
one of the 34 v0.2.0 release gates to at least one scenario.

## How To Run

### Prerequisites

```bash
# 1. Local model on the host (zero-skip policy — a missing model is a red run):
#    OMLX (mlx_lm.server) serving an OpenAI-compatible endpoint on 127.0.0.1:8000.
curl -s http://127.0.0.1:8000/v1/models | head

# 2. Python deps + browser:
pip install -e ".[dev]"
python -m playwright install chromium

# 3. Full stack (API :8100, UI :3001, worker(s), MinIO, Postgres, Redis, telemetry):
docker compose --env-file .env.local --profile local --profile test up -d
```

### One command

```bash
make docker-test-v02      # scripts/docker-test-v02.sh — preflight, build, up, L0–L13, report, down
make test-e2e             # Playwright browser E2E (in-process stack; also runnable vs live stack)
```

### v0.2.0 scenario track

```bash
scripts/docker-test-v02.sh               # full v0.2.0 container + scenario suite
scripts/docker-test-v02.sh --no-build    # reuse the current image
scripts/docker-test-v02.sh --only S6,S7  # subset
```

Flags mirror `scripts/docker-test.sh`; evidence lands in `field_test/v0.2.0/docker/` and the
report in `docs/field-test/v0.2.0/DOCKER_TEST_REPORT.md` (zero-skip enforced).

## Notes

- Do **not soften scenarios to pass** (WBS M61 notes). Any gate that cannot be demonstrated
  blocks release; findings get a dedicated fix cycle (M61-10) and are re-verified.
- The container/API/UI layers are validated separately by [docker-test-plan.md](docker-test-plan.md);
  the real-agent certified lifecycle is in [field-test-plan.md](field-test-plan.md).
- Screenshots live under `screenshots/<scenario-id>/` and are regenerated by the Playwright
  layer so reruns are repeatable.
