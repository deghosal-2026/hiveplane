## 4. Failure detail

### 4.1 L4 — certification below the production threshold

`test_register_certify_run_and_deliver` registered `repo-agent`, ran the
benchmark against the **real local model** (`Qwen3.5-4B-4bit` via the
`omlx/qwen3.5-4b/4bit` identity), and received a valid certification record —
but with status **`uncertified`** rather than `certified`:

```
assert record["certification"]["status"] == "certified"
AssertionError: assert 'uncertified' == 'certified'
```

This is **not** a wiring failure: the certification ran end to end through the
real adapter path (the earlier `run_events` 500 is fixed). It is a genuine
result that the 4B local model does not clear the repo-agent production
threshold (90% pass rate with no critical failures). The task-level breakdown
(which corpus tasks failed) has not yet been captured — see §6.

### 4.2 L3 — attestation failed signature verification (root cause found, fixed)

`test_run_detail_screen` errored while creating its seeded run:

```
AssertionError: {'detail': "attestation 'att-b7d392e5cb9d' failed signature verification"}
```

**Root cause:** L6 restarts the api container. Compose did **not** set
`HIVEPLANE_CERTIFICATION__SIGNING_KEY_FILE`, so the Ed25519 signing keypair
lived only in process memory and was regenerated on every restart. Attestations
created before the restart (e.g. by L4) then failed verification afterwards.
This is a real field-test bug, not a test artifact (#125 added key persistence,
but the Docker stack never enabled it).

**Fix applied (pending re-run):** compose now sets
`HIVEPLANE_CERTIFICATION__SIGNING_KEY_FILE=/app/.hiveplane/checkpoints/attestation.pem`
on the persistent `checkpoint-data` volume (see §5).

## 5. Fixes applied since this run (pending re-run)

1. **Postgres event sequencing (the 500s).** `PostgresRunStore.add_event`
   assigned the event sequence from a separate read and used
   `(max_seq or -1) + 1` — Python treats `0` as falsy, so once the first event
   (sequence 0) existed, the next event was also computed as 0 and collided on
   the composite PK `(run_id, sequence)`. Now the sequence is computed inside
   the write transaction as `0 if max_seq is None else max_seq + 1`. Added a
   Postgres-gated regression test (`test_event_sequences_are_assigned_atomically`).
   This bug was invisible to unit tests (the Postgres store tests are skipped
   without a DB) and only surfaced under the docker stack — exactly what this
   suite exists to catch.
2. **Operator UI port.** The UI listened on container `:3001` but compose mapped
   `host:8000`, so the UI was unreachable via Playwright. Compose now maps
   `3001:3001` and the healthcheck checks `:3001`; host port `8000` stays
   reserved for OMLX.
3. **Attestation signing key persistence** (§4.2) — compose env + volume.
4. **L5 rewrite.** `/policy/evaluate` cannot evaluate tool-level policy (it has
   no workload tool spec), so L5 now exercises the real admission gate
   (uncertified destructive workload refused production, admitted to sandbox)
   and the spend surface.
5. **L1 observability polling.** Tempo returns 503 for ~15s after start; L1 now
   retries up to 90s instead of failing once.
6. **Report generator.** Fixed the status→field mapping (`failure` → `failed`)
   that crashed report rendering on any failed test; added a failure-case test.

## 8. How to reproduce

```bash
# Requires: Docker daemon running, and OMLX serving 127.0.0.1:8000
make docker-test            # wraps scripts/docker-test.sh
```

The runner preflights the local LLM and **fails (never skips)** when it is
unavailable. Host ports are remapped (Postgres 55432, Redis 56379, Grafana
33000, Prometheus 39090, Tempo 33200, OTLP 44317/44318, webhook-sink 58081) to
avoid collisions with a developer machine; the API is on `:8100` and the UI on
`:3001`.
