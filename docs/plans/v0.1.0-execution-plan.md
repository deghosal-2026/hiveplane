# HivePlane v0.1.0 — Execution Plan

> Status: draft. Working plan for the v0.1.0 build.

## Objective

Prove the certified control loop with three real agent workloads: register, certify against a benchmark, gate production admission, run under budget/policy/sandbox, intervene, deliver results, and observe the fleet.

## Sequencing

Follow the [WBS v0.1.0](../wbs/v0.1.0/wbs-v0.1.0-index.md) in order:

1. Part 1 — Foundation & Data Models (M1-M2)
2. Part 2 — Registry Service (M3-M4)
3. Part 3 — Certification Pipeline (M5-M7) ← the thesis
4. Part 4 — Run Lifecycle & Execution API (M8-M10)
5. Part 5 — Policy Engine & Approvals (M11-M12)
6. Part 6 — Budget Enforcement (M13)
7. Part 7 — Execution Sandbox & Tool-Output Shaping (M14-M15)
8. Part 8 — Runtime Adapters & Conformance (M16-M17)
9. Part 9 — State Store & Persistence (M18)
10. Part 10 — Telemetry & Observability (M19-M20)
11. Part 11 — CLI & Operator UI (M21-M22)
12. Part 12 — Field Test (M23)
13. Part 13 — Release Readiness (M24)

## First Step

Define the workload manifest schema and the smallest control loop, then the certification gate:

1. register workload
2. run benchmark + certify
3. refuse production admission when uncertified
4. submit task → persist state transitions → enforce budget
5. stop run from operator API

**Why this first:** it proves the thesis (certified production) with real workloads instead of speculative architecture.

## Working Agreements

- one milestone at a time, exit gate before advancing
- every milestone exit requires: all tests pass, coverage > 95%, ruff clean, mypy strict clean, docs updated, changes committed and pushed
- the certified control loop ships before broad UI
- adapters stay behind the contract; nothing framework-specific leaks into core
