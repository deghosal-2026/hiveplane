# HivePlane v0.1.0 — Execution Plan

> Status: draft. Working plan for the v0.1.0 build.

## Objective

Prove the control loop with three real agent workloads running through one lifecycle, with budget enforcement, approvals, intervention, and fleet observability.

## Sequencing

Follow the [WBS v0.1.0](../wbs/v0.1.0/wbs-v0.1.0-index.md) in order:

1. Part 1 — Foundation & Data Models (M1-M2)
2. Part 2 — Registry Service (M3-M4)
3. Part 3 — Run Lifecycle & Execution API (M5-M7)
4. Part 4 — Policy Engine & Approvals (M8-M9)
5. Part 5 — Budget Enforcement (M10)
6. Part 6 — Runtime Adapters (M11-M12)
7. Part 7 — State Store & Persistence (M13)
8. Part 8 — Telemetry & Observability (M14-M15)
9. Part 9 — Operator UI & CLI (M16-M17)
10. Part 10 — Field Test (M18)
11. Part 11 — Release Readiness (M19)

## First Step

Define the workload manifest schema and the smallest control loop:

1. register workload
2. submit task
3. persist state transitions
4. enforce budget
5. stop run from operator API

**Why this first:** it proves the category with real workloads instead of speculative architecture.

## Working Agreements

- one milestone at a time, exit gate before advancing
- the control loop ships before broad UI
- adapters stay behind the contract; nothing framework-specific leaks into core
